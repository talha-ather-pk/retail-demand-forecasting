# Corvane forecasting dashboard: design and implementation notes

Everything is generated by [`scripts/build_pbip.py`](../scripts/build_pbip.py). Re-run it after changing the script, open `Corvane.pbip` in Power BI Desktop (November 2025 release or later) and click **Refresh**. The CSV folder is the `DataFolder` parameter (Transform data → Edit parameters).

It uses the same design system as the Harbor & Pine dashboard (project 02): custom theme `theme/Corvane_Executive.json`, navy sidebar with navigation and synced filters, live filter line under each page title, KPI tiles with a coloured comparison line, and a title plus a one-line business question on every visual.

## Data model

```
                       dim_date (generated in Power Query, 2023-01-01 .. 2026-02-11)
                     /      |       \
          fact_sales   fact_forecast   fact_backtest (long: one row per store-day-model)
                     \      |       /
                         dim_store ── competitor_effects
   driver_effects (stand-alone: chain-level regression estimates)
```

| Table | Grain | Source |
|---|---|---|
| `fact_sales` | store × day, 2023–2025 | `daily.csv` (history rows only) |
| `fact_forecast` | store × day, 1 Jan – 11 Feb 2026 | `forecast_2026.csv` (ensemble, P10, P90, per-model columns) |
| `fact_backtest` | store × day × model, three 42-day windows | `backtest_predictions.csv`, unpivoted in Power Query so "model" is a normal slicer/axis field |
| `dim_store` | store | `stores.csv` + derived Yes/No attributes |
| `dim_date` | day | built in Power Query (week start, month, weekday with sort columns), marked as date table |
| `driver_effects`, `competitor_effects` | effect / store | `drivers.py` output |

`_Measures` holds 75 measures (51 visible) in display folders; implicit measures are disabled and every column is `summarizeBy: none`.

## Key measures

| Measure | Logic |
|---|---|
| `Forecast`, `Forecast P10`, `Forecast P90` | Sums of the forecast columns |
| `Sales Same Dates LY` | Actual sales on the forecast dates minus 365 days (same calendar dates, so 7-day blocks hold the same weekdays and New Year's Day lines up). Implemented with `TREATAS` over the forecast dates in context |
| `WAPE` | Σ\|prediction − actual\| ÷ Σ actual over usable days (open, no POS outage), evaluated per model in context |
| `WAPE Selected Model` / `WAPE Baseline` / `Error Reduction vs Baseline` | The model actually used for 2026 (read from `fact_forecast[model]`) against the same-weekday-last-year baseline |
| `Backtest Actual` | Actuals counted once even though the backtest table is long (one row per model) |
| `Store Forecast Rank` | `RANKX` over the selected stores |
| `Filter Context`, `Title Forecast Trend`, `Title Store`, `Title Tooltip` | Dynamic text |
| `WAPE Heat`, `Model Color`, `vs LY Color`, `Effect Color` | Conditional-formatting colours |

## Pages

| Page | Questions | Visuals |
|---|---|---|
| **Forecast Overview** | How much will we sell in the next 6 weeks, how sure are we, and how does it compare with last year? | 5 KPI tiles, daily actual + forecast with P10/P90 lines (day tooltip), weekly outlook matrix, forecast by region, store ranking |
| **Forecast Accuracy** | Can we trust the forecast? Where does it miss? | 4 KPI tiles, WAPE by model, WAPE by backtest window × model heatmap, actual vs ensemble vs baseline over the three backtests, store × model heatmap |
| **Sales Drivers** | What moves daily sales and by how much? | Promo lift by format, payday, competitor KPIs; effect bar chart with true values and CIs in the tooltip; competitor distance vs sales lost; weekday × format pattern |
| **Store Detail** (drill-through on store) | Everything about one store | Dynamic title, back button, store KPIs, store forecast with range, store profile, store backtest |
| Day snapshot (tooltip) | Hover detail for a date | Forecast, actual, P10, P90 |

## Using it

* **Navigate:** sidebar menu (Ctrl + click in Desktop; plain click once published).
* **Drill through:** right-click a store in the ranking, the heatmap or the scatter → **Drill through → Store Detail**; the back arrow returns.
* **Filters:** Region, Store format and Store are synced across pages. The driver estimates are chain-level and do not change with filters.

## Finish in Power BI Desktop (optional)

1. **Publish** for a shareable link (synthetic data, so Publish to web is fine).
2. Button hover state: Format → Style → State *On hover* → Fill `#16314F`.
3. Mobile layout: View → Mobile layout, drag the KPI tiles and the forecast chart onto the phone canvas.
